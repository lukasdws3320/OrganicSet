# InstagramReferenceHub — AGENTS.md (fonte de verdade)

Biblioteca local-first de referências de Reels/vídeos do Instagram: importa link → baixa vídeo + capa + legenda + métricas públicas → organiza por clientes/experts, categorias, tags, coleções → reproduz offline.

## Fontes compartilhadas — reconstrução autorizada em 05/11/2026

O Hub é consumidor das fontes declaradas em `experts/perfis.json`; consultar `brain fontes --check`. **Tarefas** têm banco canônico no vault e domínio/CLI comum (`server/tarefas.ts`, `scripts/tarefas.ts`), sem precisar do servidor para listar ou editar. A tabela antiga em `library/database/irh.sqlite` é snapshot congelado, nunca fallback.

`.claude/skills/` deste projeto é **alias**, não cópia: fonte canônica em `.claude/skills/`. As quatro skills de conteúdo e a identidade visual foram relocalizadas byte a byte; caminhos relativos e aliases dos harnesses continuam válidos. Não recriar nem duplicar o procedimento no repo.

O serviço gerenciado inicia por `bun run app:sem-retomada` (`--sem-retomar`): servir UI/API não retoma automaticamente produção, importações, ângulos, calendário ou lembretes. Ações explícitas continuam nos mesmos controladores/autorizadores. `library/` continua neste projeto por exceção registrada, sem alegar que a execução de mídia inteira já foi externalizada.

## Entrada para agentes — UI e chat

**O Hub é o front; o backend é a verdade** (regra do Matheus, 01/11 e 03/11/2026). A execução fica registrada em arquivos do backend (`producao-workflow.json`, `REGISTRO.md`, `Postagens.md`), e o Hub só mostra, além das configs dele. Regras fixas de execução: início de `.claude/skills/replicar-referencia/etapas/execucao/SKILL.md`.

Produção preparada → `.claude/skills/replicar-referencia/etapas/execucao/SKILL.md`. `GET/POST /api/replicacoes/<id>/execucao` e CLI `executar` compartilham fila, gerador, anexos, tentativas e decisões. O backend chama ChatGPT nativo pelo Codex CLI, inclusive quando o chamador é Claude. Imagens Flow aguardam aprovação; reprovação exige motivo; aceitação libera vídeo automaticamente. Enviar próximos jobs sem aguardar render, coletar depois e preparar edição FFmpeg/OpenCut. Pequenas sobras nas bordas da fala vão para edição; não geram retake automático. Nenhuma troca de LLM autoriza repetir análise válida ou recriar estado.

Pedido de importar, replicar vídeo/carrossel, gerar prompts para outro chat ou retomar produção começa em `.claude/skills/reference-hub/SKILL.md` e `docs/execucao-por-chat.md`, mesmo se a referência ainda não estiver cadastrada. `scripts/hub.ts` chama a mesma API da UI, sem banco ou workflow paralelo. A skill atual de vídeo é `replicar-referencia`; dtcwinner é compatibilidade histórica. Chat web sem ferramentas locais recebe pacote com arquivos, legenda, identidade e prompt autossuficiente. Contexto local não é transferido pelo nome do expert. Orgânico/pago é contexto de uso, não outro executor.

Falhas de execução e regressões: `docs/execucao-erros-e-regressoes.md`. Manutenção do processo corrige o módulo responsável e seu teste, além da skill compartilhada quando houver instrução conflitante. Não resolver apenas o estado de uma produção nem criar regra restrita à sessão. Para imagens e vídeos de fundo idênticos na mesma REF, a fila compartilha a origem entre avatares (`sharedFrom`/`waiting_shared`); a interface só reflete essa decisão.

## Nomenclatura de referência e produção

Imagem inicial pode alimentar vários shots. Para react/selfie/talking head recorrentes, aplicar a reutilização definida em `.claude/skills/replicar-referencia/etapas/prompts-imagem/SKILL.md`; a quantidade de clipes não determina a quantidade de imagens a gerar.

Vocabulário canônico em `GLOSSARY.md`: **trecho de referência** = recorte analisado do original; **take de referência** = momento visual interno; **imagem inicial** = imagem preparada para iniciar o shot; **shot** = uma geração contínua de vídeo; **clipe** = arquivo resultante. A aba Referência conta trechos; a aba Produção conta os shots do plano Flow vinculado. Exemplo REF0159: 9 trechos na referência, 4 shots no plano de geração. Nunca usar o total de trechos ou takes como quantidade de vídeos a enviar.

Compatibilidade: `replicacao.json.shots` e os IDs `SHOTxx` da análise são legados dos trechos originais. Os IDs de arquivo/Flow permanecem estáveis; a apresentação numera os shots do plano em sequência e mostra a origem em `sourceShots`/`sourceTakes`. `server/production-terms.ts` concentra os rótulos e a contagem; a API inclui `number`, `label`, `sourceLabel`, `summary` e `terminology` para continuidade por outro agente. Proveniência ausente permanece explícita. O checklist manual antigo não define o plano de geração.
Pedidos pelo número exibido (ex.: “Shot 02”) são resolvidos por `number`/`label` na API de produção antes de localizar o `id` de arquivo ou enviar uma geração. O número exibido pode diferir do ID legado preservado.

## Execução para vários experts

Direção contextual e cadência (26/10/2026): a skill `replicar-referencia` orquestra os módulos locais de contexto, cadência e prompts/revisão, além do formato. Cada executor lê os módulos aplicáveis; o briefing resumido não os substitui. `scripts/revisar-cadencia.ts` é a análise local por timestamps, sem alterar dados ou abrir Flow. Novos exports exigem direção vocal resolvida e medição da fala; gênero não determina voz adulta e a janela de montagem não é piso de duração. Procedimento completo na skill, sem transplantar defaults históricos da OP 001.

Destino vigente: imagens via Nano Banana/ChatGPT conforme o trabalho → Flow com Veo 3, tanto DTC quanto experts. Frames é a preferência habitual; Elements/Ingredients depende da composição. Voz cadastrada é opcional por padrão; exigência do Bruno pertence ao perfil dele. Análise identifica o formato antes de selecionar módulo/prompt; o registro atual não cobre automaticamente podcast e todos os formatos futuros.

Ao criar ou retomar imagens/vídeos no Flow, usar a fila da skill local (`replicar-referencia/etapas/execucao`), em qualquer formato: o agente chama `scripts/hub.ts` e segue `nextAction`, sem chamar o controlador nem acionar navegador. `GoogleFlowMCP/docs/execucao-compartilhada.md` descreve o controlador que a fila usa. Perfil de identidade/configuração por expert em `library/experts/<slug>/producao.json`: nome lógico do avatar, contact sheet físico com SHA-256, projeto Flow e configurações/voz desse expert. `server/expert-production.ts` valida o perfil; `scripts/exportar-lote-flow.ts` o incorpora ao novo plano. Não herdar perfil de outro expert quando este estiver ausente. Preferências históricas específicas permanecem restritas ao próprio expert.

Lotes entre personagens seguem `GoogleFlowMCP/docs/escala-personagens.md` e `docs/execucao-eficiente.md`: perfil + política de áudio + seleção de imagem próprios, checagem offline de todos antes de enviar e diretórios/projetos isolados. Uma aba é serial; abas vinculadas podem sobrepor envios pelo CLI, mantendo lock global de downloads. `batch-status` resume; `collect-batch` limita espera por shot sem polling LLM. `flow_identity.py` compara valores e hashes; uma menção válida de outro personagem também bloqueia. Configuração conferida não aprova timbre nem aparência do resultado.

Revisão por clipe exige recibo `flow-clip-review/v1` vinculado ao hash da versão final, conforme o controlador. API/interface expõem `reviewStatus` separado de `status: baixado`; prosa em `manifesto.revisao` não é aprovação. Retake invalida recibo antigo. `build-delivery` e `audit-delivery` são os comandos canônicos para entrega parcial/final; manter a aprovação humana separada.

O builder genérico `GoogleFlowMCP/scripts/flow_reviewed_frames.py` usa base + revisão de cadência + manifesto `flow-selected-images/v1`, com REF/expert/avatar/hash do contact sheet. A transação `flow_execute_shot` / `execute-plan` automatiza projeto, coleção, upload da imagem ausente, vínculo do ID exato, prompt, voz e configuração; o padrão faz apenas preflight. A skill global do Claude é symlink para a fonte local; atualizar a fonte, sem criar uma cópia divergente em outro harness.

## Voz (desde 22/10/2026)

## Análise e fabricação modular (29/10/2026)

`replicar-referencia` roteia etapas independentes de contexto, análise visual, cadência, prompts de imagem, prompts de vídeo e revisão; `replicar-carrossel` executa o formato de slides. O contrato `fontes.visual` guarda os dois recibos/hashes, preservando mapas Gemini legados. Transcrição AssemblyAI permanece preferencial.

Formato, estilo por camada, ângulo editorial/câmera, identidade e voz são eixos distintos. Novos formatos têm módulo próprio; nomes ainda não definidos pelo usuário não inventam convenções. `server/prompt-factory.ts` adapta anexos para ChatGPT/Nano Banana e retorna jobs separados de fundo/react; a UI e a API usam a mesma fábrica. React + animação exige ações e presença por camada, inclusive segmentos só talking head. Contact sheet não é obrigatório para fundo/objeto/carrossel sem substituição de identidade. Voz é descrita em linguagem natural da personagem, sem @VOZ obrigatório. Entrega manual inclui os prompts integrais no chat.

Novos planos de vídeo exportam `timingEvidence` com hash/caminho da transcrição, intervalo de palavras e segundos medidos. O controlador valida a fala literal e os timestamps; a heurística legada de 3,2 palavras/s não prevalece sobre essa evidência. Piloto parcial não move toda a referência para Edição quando há trechos fora do plano.
